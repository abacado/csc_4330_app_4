# Demo and submission

## Before recording

- Confirm the required duration with the instructor; do not guess a video limit.
- Verify all six games are playable and marked ready. The framework currently includes five starters, not six finished games.
- Run the automated build and open its test summary, downloadable reports, and release APK.
- Install the release APK on an Android device; test the server connection in that build.
- Use two distinct guest sessions for online play and verify Supabase is awake and reachable.
- Open the correct repository and public task-board URLs while signed out.
- Test microphone volume and screen readability with a short sample recording.

## Suggested flow

1. Explain the point: “Pocket Arcade brings six familiar games into one place, with quick local play and a private online match with a friend.”
2. Show the game library and guest profile. Point out that there is no long signup.
3. Give each completed game a concise interaction and explain what the viewer is seeing.
4. Show one local completion and its Activity entry.
5. Create a Tic-Tac-Toe room, join from a second guest, and play alternating turns. Explain that Supabase stores the shared board and checks turns.
6. Show the resulting win/loss and the corresponding database records. This demonstrates the required server component.
7. Show the organized public task board, contributions, successful build, and visible tests report.
8. Close with the team members and a brief statement of what works.

Record at a readable resolution, ideally 1080p. Keep narration clear and at a normal pace. Export MP4, watch the whole file, and confirm the ending is not cut off. Upload early enough to verify the final submission links.
